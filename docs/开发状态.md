## M9 交付物（应用使用统计）

**需求来源**：需求文档 v0.5（2026-09-18）—— 解冻「窗口追踪 / 空闲检测」两条原非目标，
新增 F1.3 前台应用采集与 F7 应用使用统计。触发原因：用户要「每天的应用时长统计」，
而原纯截图链路的 `content_json.distribution` 只有 AI 推断的**活动类别占比**，无应用名、无时长。

**新增/改动文件**：

| 文件 | 内容 |
|---|---|
| `collector/app_usage.py` | **新增**：`_elapsed_seconds`（tick 回绕）、`idle_seconds`、`foreground_process_name`、`AppUsageCollector` |
| `storage/db.py` | 加 `SCHEMA_APP_USAGE` 表 + 3 个接口（接口扩到 16 个，末尾变更记录已补） |
| `storage/cleanup.py` | 加 `cleanup_app_usage`（保留 90 天） |
| `scheduler/jobs.py` | 加 `run_app_usage`（工作时间门控）+ `app_usage` interval job；`run_cleanup` 兼顾两个保留期 |
| `config.py` | 加 `storage.usage_retention_days: 90` |
| `ui/api.py` | 加 `get_app_usage` + 进程名→显示名映射 `_DISPLAY_NAMES` |
| `web/index.html` / `app.js` / `style.css` | 新增「应用统计」页签：横向条形图（主图）+ 饼图（切换）+ 日期选择；引导页隐私告知补一条。**2026-09-26 起改为总览页卡片 + 竖向柱状图**，见文末对应节 |
| `tests/` | 新增 `test_collector/test_app_usage.py`、`test_storage/test_db_app_usage.py`；更新 `test_db.py` 契约表与 `test_jobs.py` 的 job 集合断言 |

**关键实现约定（勿改）**：

- **`duration_s` 写入时算死**，查询侧不乘任何间隔。间隔可配（2/5/10 分钟），
  若查询时按"当前间隔"换算，用户改一次设置就会让全部历史时长失真。
- **`GetLastInputInfo` 是 32 位计数器、49.7 天回绕**，相减必须 `& 0xFFFFFFFF`，
  否则每隔一个多月会出现一条"空闲 40 亿秒"把当天统计废掉。
- **取进程路径用 `PROCESS_QUERY_LIMITED_INFORMATION`(0x1000)** 最低权限句柄，
  否则对管理员权限进程取不到名字；失败只跳过本轮，不影响截图采集。
- **只存进程名**（不调 `GetWindowText`），排除自身进程 `HenanDiary`。
- 应用采样是**独立 job**（id `app_usage`），与截图各自跑：AI 失败或截图失败不连坐应用时长。
- 图表**手写**（div 宽度百分比 + 内联 SVG 扇形），不引任何图表库——保持零构建。

**测试**：M9 单线交付时 `163 passed`（原 139 + 新增 24）；与远程三轮收尾合并后**合计 230 passed**。
实机探针验证通过：
`idle_seconds` 正常返回、`foreground_process_name()` 取到 `WorkBuddy`。

## M8 真机验证与修复（2026-09-16 凌晨，进行中）

用户实跑 `python main.py` 发现并修复三个问题：

1. **深色标题栏报错（已修，后被 2 取代）**：`_dark_title_bar` 里 `int(window.native.Handle)`
   抛 TypeError——pythonnet 的 `IntPtr` 不能直接 int()，要 `.ToInt64()`。
2. **关闭询问/按钮全部「无响应」根因 = UI 线程死锁**：`on_closing` 在 WinForms
   FormClosing 回调（UI 线程）里**同步**调 `window.evaluate_js`，而 evaluate_js
   内部要 Invoke 回同一 UI 线程等泵消息 → 互等死锁，整个窗口冻结，
   弹窗虽出但按钮全没反应。**修复：evaluate_js 移到独立 daemon 线程再返回拦截。**
   另外 closing 事件语义反直觉（`webview/event.py` Event.set：handler 返回 **False**
   才置 args.Cancel=True 取消关闭），原实现恰好返回对了但注释与代码互相误导，已改注释留档。
3. **顶栏白边 → 干脆去标题栏**：用户要求连原生标题栏一起干掉。
   `frameless=True, easy_drag=False`，HTML 自绘 34px 深色顶栏
   （`#titlebar`，class `pywebview-drag-region` 仅供拖动白名单，
   `user-select:none`）；按钮接新 API `minimize` / `toggle_maximize`
   （后者用 `api._maximized` 记状态，Window.maximized 属性不可靠）/ X 复用 showCloseAsk。

**验收**：`pytest` 139 项全绿（api 新增两方法未破坏既有断言）。
**待办**：真机复验 frameless 拖动/缩放/最小化/最大化/关闭询问/托盘；然后重打包。

## 2026-09-22 截图分析结构化（分支 `feat-structured-analysis`）

体检清单里产品力最强的一条：截图分析此前只吐「一句话」，日报的「时间分布」板块没有任何
可依据的数字，只能让模型对着文本再估一遍——需求文档风险 5 自己都承认「是 AI 推断，不是精确统计」。
现在把结构化前移到第一层分析，时间分布变成**按分类逐条计数**。

**数据流变化**

```
截图 → 压缩 → AI(prompt 要求 JSON) → parse_analysis 解析 → 落库(app/category/desc)
                                                              ↓
                                        日报 prompt 附「本地统计」→ 模型照抄，不重估
```

**改动（3 笔）**

| 提交 | 内容 |
|---|---|
| `9f50afd` | prompt 改要 `{app, category, desc}`，category 取自封闭枚举（编码/终端/文档/沟通/会议/浏览/设计/影音/游戏/其他）；`collector.parse_analysis` 容错解析；`screenshot_analysis` 表加 `app`/`category` 两列 + `init_db` 的 ALTER TABLE 迁移 |
| `911d91a` | `report._distribution_lines` 按 category 逐条计数算占比，写进日报 prompt 并要求照抄；记录行带分类 |
| `cdebd29` | 时间线返回并渲染分类标签 |

**关键取舍**

- **category 必须封闭枚举**：不固定的话每天类别名都不一样，本地统计会变成一盘散沙。
  模型给出枚举外的值时归「其他」。
- **解析必须容错**：采集每 5 分钟一轮、无人兜底。模型夹带客套话、裹 ```` ```json ```` 代码块、
  甚至整段不给 JSON，都要能落地——解析不了就整段当描述存下来，绝不因此丢掉一轮素材。
- **老库要能升级**：`CREATE TABLE IF NOT EXISTS` 不会给已有表补列，`init_db` 里加了一道
  `ALTER TABLE`（`db.ADDED_COLUMNS`，幂等）；迁移前的旧行两列为 NULL，统计时归「其他」。
- **接口变更已走契约**：`save_screenshot_analysis` 增加 `app`/`category` 两个可选参数，
  `FROZEN_SIGNATURES` 同步更新并注明变更日期（开发规范 3.1：接口变更要显式登记）。

**验收**：`pytest` **192 项全绿**（本次前 179 项）。新增覆盖：解析的四种形态
（纯 JSON / 代码块+客套话 / 纯文本回落 / 缺 desc 用 app 兜底）、野生分类归「其他」、
结构化字段落库与读回、旧表迁移、本地统计的占比与排序、老数据归「其他」、
prompt 里带上统计与分类。

**未验证**：真实模型下的字段质量（分类是否稳定、app 名是否可用）需要配好 Key 实跑一天才能判断；
本机验证全程用假 AI。若模型频繁给空 category，可考虑在 prompt 里加 few-shot 示例。

**自查抓到的一个坑**：`PIE_COLORS` 初值曾写死 `THEME_COLORS.dark`，而 `applyTheme()`
遇到「皮肤没变」会 early-return —— 于是明亮用户**重启后**（缓存与后端都是 light）图表配色会
停在暗色那套。已改为初值走 `pieColors()`。**这类只在重启路径上出现的错，静态截图照不到。**

**验收**：`pytest` 239 项全绿。前端用 `build/theme_demo.html`（复用真实 `web/style.css`）
铺开顶栏 / 侧栏 / 徽标 / 报告正文 / 危险区 / 皮肤分段控件 / 饼图与柱状图，明暗各截一张对色。
**未验证**：真机切换观感；`localStorage` 首帧提示在 WebView2 的 `file://` 下是否可用
（不可用只表现为启动闪一帧，不影响功能）。

## 2026-09-26 应用统计入口调整（并入总览页 + 竖向柱状图）

「应用统计」不再占一个侧栏页签（侧栏 5 项 → 4 项），改为总览页的一张卡片：只看**今天**，
不再需要日期选择器。改动**只在 `web/` 三个文件**，后端与数据口径零改动，测试维持 230 项。

| 决策 | 做法与理由 |
|---|---|
| 取消日期选择 | 后端 `get_state()` 的 `date` 作为唯一「今天」，前端不再用 `toLocaleDateString` 各算一次（跨零点会与之错位）。**界面因此只呈现今天**——历史日期的数据仍在 `app_usage` 表里、接口 `get_app_usage(date)` 保留，但界面暂无入口 |
| 卡片不进 10 秒轮询 | 应用采样是 5/10 分钟粒度，跟着状态轮询重绘只会闪。取数挂在 `go('overview')` 上，与 `loadOverview()` 一起跑 |
| 主图改竖向柱状图 | 数值在柱顶、应用名在柱下，旧横向条形图的规则（`.bar-row` / `.bar-name` 定宽 / `.bar-fill.other`）一并删除 |
| 两种图共用一套配色 | 按序号取 `PIE_COLORS`，同一应用在饼图/柱状图里颜色一致；切图**只重渲染、不重新取数**（`_ovUsage` 缓存） |
| 柱宽与间距 | `.bar-col` 用 `flex:1 1 0; min-width:0; max-width:100px`——**同时**满足「柱心间距一致 / 名字尽量完整 / 少项时不散开」。改过三轮：`flex:0 1 auto` 间距忽宽忽窄，纯 `flex:1` 会把少项柱子推到右侧 |
| topN 8 → 5 | 两种图统一 `topN(items, 5)`，超出并入「其他」 |

**验收**：`pytest` 230 项全绿（本次不涉测试改动）+ `node --check web/app.js`。
前端用 `build/bar_demo.html` 铺 2 项 / 6 项（含「其他」）/ 单柱三组边界数据，
经系统自带 Edge 无头截图比对柱宽与间距（`build/bar_demo.png`）。
**未验证**：真机里总览页滚到卡片的手感、窄窗口下柱状图的挤压表现。
