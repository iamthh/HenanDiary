## M1 交付物

- `storage/db.py`：`init_db` / `save_screenshot_analysis` / `get_today_analyses` 落地（每操作独立连接 + WAL）
- `ai/client.py`：`AIClient.analyze_image`（OpenAI 兼容）+ DPAPI `encrypt_key` / `decrypt_key`；`tools/set_api_key.py` 一次性配 Key 脚本（M4 引导做完后退役）
- `collector/screenshot.py`：纯内存截图 + `run_once`（工作时间门控、enabled 开关、失败只记日志不崩循环）+ APScheduler interval 调度

**验收**：2 分钟间隔实跑 8 分钟，`screenshot_analysis` 表入库 4 条真实 AI 分析（端点 sensenova-6.8-flash-lite）。

**验收中发现并修复**：推理模型 100 token 预算全被思维链吃掉、正文返回空 → `max_tokens` 调至 1024。
**遗留提醒**：M2 接同一类推理模型时注意 token 预算与 reasoning 字段；截图分析 Prompt 可考虑约束输出格式。

## 接口补充（2026-09-14，已确认）

技术方案第四节的接口清单按需求跑不通 4 处，已在 M0 阶段补齐（此时无调用方，改动成本最低）：

| # | 问题 | 处理 |
|---|---|---|
| 1 | `pending_report` 只读不可写，D14「失败保留素材、下次补生成」落不了地 | 补 `add_pending_report` / `delete_pending_report` |
| 2 | `is_overwritten` 无回写入口，00:30 覆盖版无法标记 | 不新增接口，给 `save_daily_report` 加 `is_overwritten` 参数 |
| 3 | F4.3 要按日期翻历史，缺列表接口 | 补 `list_daily_reports` / `list_weekly_reports`（只返回元信息） |
| 4 | `weekly_report` 只有写没有读 | 补 `get_weekly_report` |

**状态归属约定**（原设计里 `ai_status` 与 `pending_report` 职责重叠，已明确）：
`daily_report` 里有行 == 该天日报已生成成功；生成失败的日期不写 `daily_report`，
只在 `pending_report` 记一笔欠账，补生成成功后销账。`ai_status` 不再扩展接口。
