# 桌面日报生成应用 — 技术方案 v2.1

> 基于需求文档 v0.3 + v0.5 变更（应用使用统计），两人团队按功能模块分工。
> 最后更新：2026-09-18
> 变更说明：v2.0 适配 v0.3 需求，砍掉窗口追踪/空闲检测，架构大幅简化。
> **v2.1 变更（2026-09-18）**：为 F7 应用使用统计**恢复**窗口 API（**仅取前台进程名**），
> 新增 `collector/app_usage.py`、`app_usage` 表、独立调度 job `app_usage`。
> **仍不引入 `psutil`**：`ctypes` 调 `QueryFullProcessImageNameW` 即可取到进程名。

## 一、技术栈总览

| 层 | 选型 | 理由 |
|---|---|---|
| **语言** | Python 3.11+ | 两人都熟；生态对 Windows 桌面工具友好 |
| **GUI** | **PySide6** | 内置托盘图标、内置 Markdown 渲染（`QTextBrowser`）、LGPL 可商用 |
| **截图** | `mss` + `Pillow` | `mss.tools.to_png()` 直接返回 PNG bytes（纯内存，✅ 已验证） |
| **定时调度** | `APScheduler` | 支持 cron 式定时、支持程序重启后补跑（misfire） |
| **AI 客户端** | `openai` Python SDK | 兼容 OpenAI 及所有国产 OpenAI 兼容 API，支持图片输入 |
| **Key 加密** | `win32crypt`（pywin32） | DPAPI 加密，Key 不落明文 |
| **打包** | **PyInstaller**（onefile） | 成熟稳定 |
| **安装包** | **Inno Setup** | 免费、中文社区成熟 |
| **依赖管理** | `uv` | 比 pip 快 10 倍以上，两人协作锁版本方便 |
| **日志** | Python `logging` + `RotatingFileHandler` | 内置，够用 |

**明确不选的**：
- ❌ Tkinter / PyQt6 / pyautogui / Nuitka / Electron（理由同 v1.0）
- ❌ ~~`psutil`~~（v0.3 已不需要，无窗口追踪）
- ❌ ~~`ctypes` 窗口 API~~（v0.3 已不需要）

## 四、数据层设计

### SQLite 表结构（B 定义）

```sql
-- 截图分析结果（保留 3 天）
CREATE TABLE screenshot_analysis (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp   TEXT NOT NULL,           -- ISO8601
    analysis    TEXT NOT NULL            -- AI 对截图的文字描述
);

-- 日报（永久保留）
CREATE TABLE daily_report (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    date        TEXT UNIQUE NOT NULL,    -- YYYY-MM-DD
    content_md  TEXT NOT NULL,           -- Markdown 正文
    content_json TEXT NOT NULL,          -- 结构化 JSON（供周报用）
    generated_at TEXT NOT NULL,
    is_overwritten INTEGER DEFAULT 0,    -- 1=被 00:30 覆盖版
    ai_status   TEXT DEFAULT 'success'   -- success / failed / pending
);

-- 周报（永久保留）
CREATE TABLE weekly_report (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    week_start  TEXT UNIQUE NOT NULL,    -- 周一日期 YYYY-MM-DD
    content_md  TEXT NOT NULL,
    generated_at TEXT NOT NULL
);

-- 待重试的 AI 任务（日报生成失败时保留素材）
CREATE TABLE pending_report (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    date        TEXT NOT NULL,
    type        TEXT NOT NULL,           -- daily / weekly
    reason      TEXT,                    -- 失败原因
    created_at  TEXT NOT NULL
);

-- 前台应用使用明细（v2.1 新增，保留 90 天）
CREATE TABLE app_usage (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp   TEXT NOT NULL,           -- ISO8601
    app         TEXT NOT NULL,           -- 进程名，如 Code / chrome（不含窗口标题）
    duration_s  INTEGER NOT NULL         -- 本次采样代表的秒数，写入时快照，不随设置变更
);
```

**`duration_s` 为什么存值、而不是查询时乘间隔**：截图间隔是可配的（2/5/10 分钟），
若查询时按"当前间隔"换算，用户改一次设置，全部历史数据的时长就跟着变，趋势图直接失真。
写入时把秒数算死，是唯一不会事后打脸的做法。

## 六、关键技术点的实现思路

### 1. 纯内存截图（A 负责，已验证）

```python
# collector/screenshot.py 核心思路
import mss, mss.tools
import base64

def capture_to_memory() -> bytes:
    """截图 → PNG bytes，全程不写盘"""
    with mss.MSS() as sct:
        sct_img = sct.grab(sct.monitors[1])
        return mss.tools.to_png(sct_img.rgb, sct_img.size)

def to_base64(png_bytes: bytes) -> str:
    return base64.b64encode(png_bytes).decode("utf-8")

# 使用流程：
# png_bytes = capture_to_memory()
# b64 = to_base64(png_bytes)
# analysis = ai_client.analyze_image(b64)  # 送 AI
# db.save_screenshot_analysis(timestamp, analysis)  # 调 B 的接口
# del png_bytes, b64  # 立即释放
```

```python
from openai import OpenAI

def analyze_image(self, base64_png: str) -> str:
    """送截图给 AI，返回文字描述"""
    response = self.client.chat.completions.create(
        model=self.model,
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": "描述这张截图中用户在做什么，用一句话概括"},
                {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{base64_png}"}}
            ]
        }],
        max_tokens=100
    )
    return response.choices[0].message.content
```

### 5. 前台应用采样（A 负责，v2.1 新增）

```python
# collector/app_usage.py 核心思路

def foreground_process_name() -> str | None:
    """取前台窗口所属进程的可执行文件名（不含 .exe）。失败返回 None。"""
    hwnd = win32gui.GetForegroundWindow()
    if not hwnd:
        return None
    _, pid = win32process.GetWindowThreadProcessId(hwnd)
    # 必须用 PROCESS_QUERY_LIMITED_INFORMATION(0x1000) 这个最低权限句柄：
    # 请求更高权限时，对以管理员运行的程序（任务管理器、高权限 IDE）会取不到名字
    handle = kernel32.OpenProcess(0x1000, False, pid)
    # QueryFullProcessImageNameW → 全路径 → 取 basename
    # 注意：不要调 GetWindowText —— 窗口标题常含文件名与网址，属隐私禁区

def idle_seconds() -> int:
    """系统空闲秒数（无键鼠输入）。"""
    return ((kernel32.GetTickCount() - user32.GetLastInputInfo()) & 0xFFFFFFFF) // 1000

def run_once(self) -> None:
    """一轮采样。跟随采集开关，空闲超阈值直接跳过。"""
    if not config.load_settings()["capture"]["enabled"]:
        return
    if idle_seconds() > IDLE_THRESHOLD_S:
        return
    app = foreground_process_name()
    if app:
        db.save_app_usage(now_iso(), app, interval_min * 60)
```

**三个必须处理的坑**：

1. **`duration_s` 存快照**——理由见 §四 表结构下方。
2. **`GetLastInputInfo` 是 32 位计数器，49.7 天回绕一次**。相减必须 `& 0xFFFFFFFF`,
   否则每隔一个多月会冒出一条"空闲 40 亿秒"，当天统计直接废掉。
3. **取进程名一律用最低权限句柄**，并用 try/except 兜住：权限不足时记 warning 跳过本轮，
   但**不能让它影响截图采集链路**（开发规范 1.3：不吞异常，也不连坐）。

**与截图链路的关系**：两者各自独立调度（job id `capture` / `app_usage`）。
AI 调用失败或截图失败都不影响应用时长的记录——用户在用哪个程序是客观事实，
不该因为 AI 欠费就跟着丢数据。

## 九、风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| PySide6 打包后体积过大（>80MB） | 中 | 用 PyInstaller `--exclude-module` 排除未用模块 |
| 杀软误报 PyInstaller 打包的 exe | **高** | 下载页提示 + 后续考虑买代码签名 |
| AI 图片分析成本高（96 张/天 × 图片 token） | 中 | 引导时告知用户预估成本；支持调低截图间隔到 10 分钟 |
| AI 返回格式不稳定 | 中 | Prompt 里要求 JSON 输出，代码里做容错解析 |
| 多显示器环境下截图异常 | 低 | 默认截主显示器，后续版本支持多屏 |
| 取进程名失败（权限不足 / 受保护进程） | 中 | 用 `PROCESS_QUERY_LIMITED_INFORMATION` 最低权限句柄；失败只跳过本轮并记 warning，绝不连坐截图链路 |
| 用户改采集间隔导致历史时长失真 | 中 | `duration_s` 写入时即算好存死，查询不参与换算（见 §四） |
