# 开发规范

> 两人团队共同遵守，开工前确认。
> 最后更新：2026-09-15

---

## 一、代码规范

### 1.1 基本要求

- Python 3.11+，使用类型注解（type hints）
- 每行不超过 100 字符
- 函数不超过 30 行，超过考虑拆分
- 文件顶部写模块说明（docstring）

### 1.2 命名

| 类型 | 规范 | 示例 |
|---|---|---|
| 文件名 | 小写下划线 | `screenshot.py` |
| 类名 | 大驼峰 | `ScreenshotCollector` |
| 函数/变量 | 小写下划线 | `capture_to_memory()` |
| 常量 | 大写下划线 | `DEFAULT_INTERVAL_MIN` |
| 私有方法 | 前缀下划线 | `_analyze_image()` |

### 1.3 日志

- **必须**用 `logger.py` 统一入口，禁止 `print`
- **禁止**静默吞异常（`except: pass`），要么处理要么记录要么注释说明
- 关键操作必须记日志（启动、截图、AI 调用、生成日报、错误）

```python
# 正确
try:
    result = ai_client.analyze(image)
except APIError as e:
    logger.error(f"AI 分析失败: {e}")
    raise

# 禁止
try:
    result = ai_client.analyze(image)
except:
    pass
```

### 1.4 配置

- 任何模块需要配置，都从 `config.py` 读，**禁止**自己存配置
- 禁止在代码里写死路径、Key、URL

## 二、Git 规范

### 2.1 分支

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 稳定版 | 只能从 `dev` 合并，禁止直接提交 |
| `dev` | 日常开发 | 功能分支从这里切 |
| `feat/xxx` | 功能开发 | 完成后合并回 `dev` |
| `fix/xxx` | 修 bug | 完成后合并回 `dev` |

分支命名 `xxx` 部分：英文小写，单词用 `-` 连接，2~3 个词说清主题，如 `feat/db-retry-read`。不用中文、不用下划线、不带日期。

提交粒度与分支的对应：

- 小改动（改文档、修一行 bug、加一个小接口）直接在 `dev` 上提交，**不必**每个改动都建分支
- 跨多天、涉及多文件的功能才切 `feat/xxx`，做完合并回 `dev` 即删分支

### 2.2 提交信息

格式：`<type>:<中文描述>`，**冒号后不加空格**。

| type | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 文档变更 |
| `refactor` | 代码重构（不改功能） |
| `perf` | 性能优化 |
| `chore` | 构建/工具/杂务 |

写法要求：

- 一句话说清改了什么，如 `fix:修复登录页面的空指针异常`
- **一条消息就是一整句中文短句**，不要写成 `xxx: yyy; zzz` 这种拼接式
- 一个 commit 只做一件事，不相关的改动拆开提交（如"结构重构"和"换图标"分两笔）
- 提交前先 `git status` 与 `git diff` 核对改动，暂存后用 `git diff --cached` 核对暂存内容
- 更多背景写进正文（空一行后），或记入 `docs/开发状态.md`

### 2.3 提交频率

- 完成一个小功能就提交，不要攒一大堆
- 每天至少提交一次

### 2.4 Git 易错点

| 易错点 | 正确做法 |
|---|---|
| `git add -A` / `git add .` 一把梭 | 只认 `.gitignore`，提交前 `git status` 看清会带上什么，按需 `git add <路径>` |
| 关键操作后不看状态 | 每次 `commit` / `merge` / `pull` / `push` 后补一次 `git status` |
| 手改已推送的历史 | 已推送的提交不改；要修正 msg 就新开一笔说明，别静默重写 |
| 用 `HEAD` / 分支名查历史记不住 | 用符号引用：`dev@{1}`、`main@{yesterday}`、`git reflog` |

## 三、接口规范

### 3.1 接口先行

- B 负责 `storage/db.py`，**先把所有函数签名定好**（哪怕写 `pass`），A 基于此开发
- 接口变更必须通知对方，不能偷偷改

### 3.2 数据格式

- 时间戳统一用 ISO8601 字符串：`2026-09-14T22:00:00`
- 日期统一用 `YYYY-MM-DD`
- 金额/数量统一用数字，不用字符串

---

## 四、测试规范

- 关键模块必须有测试（`storage/db.py`、`ai/client.py`、`report/generator.py`）
- 测试文件放 `tests/` 下，命名 `test_模块名.py`
- 用 `pytest` 运行

---

## 五、文档规范

- 每完成一个里程碑，更新 `docs/开发状态.md`
- 重大设计变更，更新 `docs/技术方案.md`
- 需求变更，更新 `docs/需求文档.md` 并升版本号

---

## 六、每日同步

- 早上 10 分钟口头同步：昨天做了什么、今天做什么、有没有阻塞
- 有阻塞当场说，不要憋到下班

---

## 七、禁止事项

| 禁止 | 原因 |
|---|---|
| 静默吞异常 | 排查黑洞 |
| 在代码里写死配置 | 改配置要改代码 |
| 直接提交到 `main` | 破坏稳定版 |
| 私自改接口不通知 | 对方代码会崩 |
| 用 `print` 代替日志 | 无法追踪问题 |
