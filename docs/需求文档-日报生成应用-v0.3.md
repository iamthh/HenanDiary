## 一、产品定位

**一句话**：一个装完后不用管的 Windows 桌面小工具——它每隔几分钟给屏幕拍张照，每天晚上 22:00 让 AI 看这些照片写一份日报，你打开就能看。

**不是什么**：
- 不是员工监控软件（不做上报、不做后台管理、不给第三方看数据）
- 不是时间管理/to-do 工具（不强制你打标签、不打断你）
- 不是跨设备同步产品（首版单机）

**目标用户**：需要写日报但懒得回忆的打工人、需要记录工作产出的自由职业者、想复盘自己时间去向的人。

## 二、核心原则

| 原则 | 含义 |
|---|---|
| **安静** | 不弹窗、不打断、不要求打卡，托盘图标是它唯一的"存在感" |
| **隐私优先** | 数据只存本地；截图**绝不落盘**，AI 分析完即销毁 |
| **数据可见可控** | 用户能随时暂停采集、查看采集了什么、一键清空全部数据 |
| **开箱即用** | 下载→安装→填 Key→开始工作，全流程 ≤ 3 分钟 |
| **极简** | 一个采集动作（截图），一个产物（日报），不搞多余功能 |

## 四、功能需求

### F1 采集模块（后台常驻）

**F1.1 定时截图**
- 间隔可选：10 / 5 / 2 分钟，默认 5 分钟
- **硬性约束**：截图以内存字节流直接送 AI，**禁止写盘任何位置（含临时目录、系统 temp）**
- 分析完成立即释放内存引用
- **明确告知用户**：因 Windows 虚拟内存机制，极端情况（内存不足）下内存页可能被换入 `pagefile.sys`，应用层无法杜绝
- 采集可全局一键暂停

**F1.2 采集控制**
- 托盘可一键「暂停采集 / 继续采集」
- 支持配置**工作时间段**（如 09:00-19:00 才采集）

**F1.3 前台应用采集（v0.5 新增）**
- 与截图采集**同间隔、同工作时间窗口**，读取前台窗口所属进程的**进程名**（如 `Code`、`chrome`）
- **空闲剔除**：系统无输入超过 **5 分钟**时本轮不计入（阈值暂不做成配置项）
- 跟随「暂停采集」全局开关，不另设开关
- 采集失败（权限不足、受保护进程）只跳过本轮并记日志，**不得影响截图采集链路**
- 隐私边界：**只存进程名**，不存窗口标题、不存网页地址

### F2 日报生成模块

**F2.1 定时触发**
- 每天 22:00 自动执行（时间可配置）
- **次日 00:30 自动重新生成一次，覆盖前一天**（补 22:00 之后的内容）
- 机器休眠/关机场景：次日启动时补生成，日报标注"补生成"
- 支持手动「立即生成一份」

**F2.2 AI 输入构造**
- 输入：当日所有截图的 AI 分析结论（文字列表）
- 数据量：8 小时 × 5 分钟 = **96 条**，直接送模型，无需压缩

**F2.3 AI 输出（日报板块）**
- **今日概览**：一句话总结今天主要做了什么
- **主要工作块**：按项目/任务聚类的时间段 + 做了什么
- **时间分布**：各应用/类别占比（AI 根据截图内容推断）

**F2.4 模型接入**
- 用户填 API Key，OpenAI 兼容格式优先
- Key 存储用 Windows DPAPI 加密
- 支持配置 Base URL、模型名
- 调用失败需明确告知原因（Key 无效 / 余额不足 / 网络不通）
- **失败时保留素材，下次成功调用自动补生成**；托盘图标变红提示

### F3 周报模块

- 输入：周一到周日的 7 份日报文本
- 生成时机：**每周日 22:30 自动**
- 支持手动生成
- 输出：独立的周报文件（Markdown），与日报分开存储

### F4 查看与存储

**F4.1 数据目录结构**
```
%APPDATA%\<应用名>\
├── data.db              # SQLite 主库
├── reports/
│   ├── daily/           # 日报，永久保留
│   └── weekly/          # 周报，永久保留
├── config/
│   └── settings.json    # 用户配置
└── logs/                # 应用运行日志（轮转）
```

**F4.2 日报存储**
- Markdown 格式，按日期命名（如 `2026-09-14.md`）
- 同时保存一份结构化 JSON（给程序用，供周报汇总）

**F4.3 查看方式**
- 点亮托盘图标 → **应用内窗口渲染 Markdown** 显示当日日报
- 支持按日期列表翻历史日报/周报

**F4.4 数据管理**
- 「导出全部数据」：打包带走
- 「清空全部数据」：二次确认后彻底删除
- 截图分析结果**保留 3 天**，自动清理；日报/周报永久保留

### F5 首次使用引导

- 安装后首次启动，2~3 屏引导完成：
  1. 说明采集什么、存哪里（透明告知，含截图送 AI 的隐私说明）
  2. 请求/说明所需权限
  3. 填写 API Key 并**当场测试连通性**
- 引导结束前不开始采集

### F6 打包与分发

- 安装路径默认 `C:\Program Files\`，用户可修改
- 输出 Windows 安装包（exe/msi），普通用户双击可装
- 需处理：开机自启（可选）、托盘常驻、单实例运行
- 杀软误报：下载页明确提示，用户自行加白名单

### F7 应用使用统计（v0.5 新增）

**F7.1 数据来源**
- 来自 F1.3 采集的前台进程名记录，**不经过 AI、不额外消耗 API 额度**
- 时长口径：`采样条数 × 该次写入时的采集间隔`，间隔取**写入时快照**，
  不随后续设置变更而回溯（否则用户改一次间隔，历史数据全部失真）
- 明细保留 **90 天**（`storage.usage_retention_days`）后自动清理；「清空全部数据」一并删除

**F7.2 展示**（v0.7 定入口，v0.9 改主图形态）
- **入口**：不单设页面或页签，统计卡片挂在**今日总览页**；只呈现**当天**，不提供日期选择器
- **单日应用时长排行**（横向条形图，主图）：一行一个应用，左侧应用名、中间横条按时长降序、
  条右标「时长 · 占比」；**应用名列宽由最长名字撑开，完整显示不截断**（应用名是排行里
  的必读信息，固定列宽会把 `windows-terminal.exe` 这类长名压成省略号）；
  超出 5 项合并为「其他」
- **单日占比**（饼图，切换视图）：Top 5 + 其他，图例带占比
- 两张图的配色都取自**当前皮肤**对应的图表色板（明/暗各一套，切换皮肤即换色），
  按序号取色，同一应用在两张图里颜色一致
- **跨天趋势**（堆叠柱状图）：近 N 天各应用时长 —— **未交付**（v0.5 变更说明已限定
  「本次只做单日排行与占比两张基础图」，服务层目前也只有单日接口 `get_app_usage(date)`），
  该条仍留在需求中，见 `docs/开发状态.md`「遗留事项」
- 图表由渲染层原生实现，**不引入第三方图表库**（保持"无构建、无框架"约束，见 §四 F4.3）

**F7.3 诚实标注（硬要求）**
- 页面必须标注「按 N 分钟采样估算」，**不得呈现为精确计时**
- 两次采样之间的应用切换无法捕捉，空闲时间不计入，与系统级屏幕时间统计会有出入

### F8 界面外观（v0.6 新增）

**F8.1 明暗皮肤**
- 设置页提供「皮肤」选择，**两档：暗色（默认，即原有配色）/ 明亮**。不做「跟随系统」，不做自定义配色
- **明亮档主色调为冷蓝**（`--accent` = `#1d5fcc`），底色/边框/次要文字等中性色一并转冷；
  **暗色档保持原有暖橙配色不变**。两档都不提供用户自选主色调的能力
- 取值存 `%APPDATA%\HenanDiary\config\settings.json` 的 `ui.theme`，唯一来源仍是 `config.py`；
  写入前校验（只允许 `dark` / `light`），非法值不落盘
- **选中即全局生效并自动落盘**，不要求用户再点设置页的「保存设置」
- 切换只替换 CSS 变量的取值（两档共用同一套变量名），**不改布局、不改业务逻辑、
  不触发日报/周报的调度重排**
- 两档皮肤下，正文文字与状态徽标文字的对比度均不低于 WCAG AA（4.5:1）
- 启动时的皮肤由 `settings.json` 决定；前端可用本地缓存做首帧提示以避免闪色，
  但该缓存**不是**配置来源，后端值到手后必须以后端为准

### F9 运行日志（v0.10 新增，诊断用途）

**F9.1 数据来源**
- **只读** `%APPDATA%\HenanDiary\logs\app.log`（`logger.py` 已在写的轮转日志，1MB × 5 份）。
  **不新增任何落盘、不新开日志文件、不改日志写入路径**，日志格式与轮转策略也不变
- 单次最多返回 500 条（默认 200）；当前文件条数不足时回溯已轮转的备份文件（越靠后越旧）
- 日志读取失败（例如恰好撞上轮转的文件改名瞬间）只记一条 warning 并返回空结果，
  **不向界面抛异常**；级别值无法识别时按「全部」处理，同样不报错

**F9.2 展示**
- 侧栏在「设置」之上新增「运行日志」页；列表**最新在前**，一行一条：时间 / 级别 / 正文
- 四档级别筛选：全部（默认）/ 信息 / 警告 / 错误
- `log.exception` 的 traceback 续行**必须保留换行**并入所属那条记录，不得只留首行
- 工具条含「刷新」按钮、当前条数、「打开日志目录」；结果被 500 条上限截断时如实标注
- **本页处于打开状态时每 60 秒自动刷新**；内容没有变化不重绘（不得打断用户滚动与文字选中），
  新记录插在顶部时保持用户当前的滚动位置

**F9.3 使用边界与诚实标注**
- 本页面向「界面能打开但行为不对」的问题（采集没跑、AI 一直失败）。**进程完全没起来或
  窗口白屏这类问题它无能为力**——那种情况要看 `logs\app.log` 文件本身，页面此刻也打不开
- 日志正文含本机路径、模型名、接口地址等，**只在本地展示**：页面不提供任何上传或分享入口
- 日志按级别上色属 F8.1 语义色要求的延伸：信息用次要文字色、错误用 `--bad`，警告色两档各取
  一个固定琥珀值——`--accent` 在明亮档是主色调蓝，拿它当警告色会被读成「链接」而不是「有问题」

## 五、非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 常驻内存占用目标 < 150MB；空闲时 CPU < 1% |
| 稳定性 | 连续运行 30 天不崩、不漏采；异常退出后能自动恢复并补采 |
| 隐私 | 除用户自己配置的 AI 接口外，不向任何第三方发送数据；不内置任何统计/埋点 |
| 可观测 | 本地日志（轮转），出问题能查；**禁止静默吞异常** |
| 兼容 | Windows 10 1809+ / Windows 11 |

- 账号体系、云端同步、多设备
- 团队/管理者视角的后台
- 日报自动外发（邮件/IM/网盘）

- ~~**空闲检测**（截图本身就在记录）~~ → **v0.5 解冻**：仅用于剔除挂机时间，见 F1.3

## 七、已知风险与诚实告知（将写入用户协议）

1. **截图送第三方模型**：截图内容会经过用户自己配置的模型厂商，需在引导第一屏明确告知并由用户主动确认。
2. **纯内存的局限**：应用层不主动写盘，但 Windows 虚拟内存机制下，极端情况（内存不足）可能将内存页换入 `pagefile.sys`，应用无法杜绝。
3. **杀软误报**：无代码签名，被杀软判定为可疑程序是预期内事件，下载页需提供加白名单指引。
4. **用户自备 Key 的门槛**：部分用户会因不知如何获取 API Key 而流失，需提供分步图文指引。
5. **截图是离散采样**：每 5 分钟一张，两张截图之间的事 AI 不知道。日报中的"时间分布"是 AI 推断，不是精确统计。
6. **应用时长同样是采样估算**（v0.5 新增）：按采集间隔读取前台窗口进程名，两次采样之间的应用切换
   无法捕捉，空闲超过阈值的时间不计入。页面标注为"估算"，**不得宣传为精确计时**，
   与 Windows 自带的屏幕时间统计会有出入。
7. **读取前台程序名**（v0.5 新增，需在引导第一屏一并告知）：应用时长统计会读取当前前台窗口
   所属程序的**进程名**（如 `Code`、`chrome`）。**不读取窗口标题、不读取网页地址、不记录键盘
   与剪贴板内容**；进程名只写本地库，不经 AI、不出本机。
